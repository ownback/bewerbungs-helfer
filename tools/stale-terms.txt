# Formulierungen, die in keiner Datei des Repositorys mehr stehen dürfen (tools/check_repo.py docs).
# Eine Zeile: <regulärer Ausdruck> => <Hinweis>. Geprüft wird jede Textdatei außer CHANGELOG.md und dieser Liste.
# Wer eine Aussage ersetzt, die nicht wiederkehren darf, trägt die alte Formulierung hier ein.

# Verlauf gehört in CHANGELOG.md; Doku, Schemas und Kommentare beschreiben nur den heutigen Stand
\bRunde [0-9]+ => Verlauf steht in CHANGELOG.md, die Doku beschreibt den heutigen Stand
\b[Ss]tand Runde\b => Verlauf steht in CHANGELOG.md

# Symbolzahl: wird aus assets/mappe/icons.svg gezählt
\b33 (Logo-)?Symbole\b => die Zahl der Symbole ergibt sich aus assets/mappe/icons.svg

# Erfassung bei der BA: ein Tab, ein Durchgang (references/job-search.md, Regel capture.one-tab)
\b(in einem |im |einen |jeweils )?neuen Tab\b => alle Anzeigen nacheinander im selben Tab erfassen
\bneuer Tab (pro|je) (Anzeige|Stelle)\b => alle Anzeigen nacheinander im selben Tab erfassen

# Persönliche Daten im Lebenslauf: zwei Spalten nach Inhalt breit, nicht gleich breit
(?i)(persönliche[n]? daten|cv-facts|datenbox)[^\n]*\bgleich breit => die Spalten der persönlichen Daten sind nach Inhalt breit (repeat(2, auto))
(?i)\bgleich breit[^\n]*(persönliche[n]? daten|cv-facts|datenbox) => die Spalten der persönlichen Daten sind nach Inhalt breit (repeat(2, auto))

# Vorlage: Markup und Design stehen in assets/mappe/, die Master-Vorlage ist ein Bauergebnis
\bDesign nur in der Skill-Vorlage\b => Design nur in den Quellen unter assets/mappe/
\bStartkapsel bündig unter der Glasleiste\b => die Kapsel steht mittig in ihrer Spalte
\.page-footer\b => es gibt keine Fußzeile; die Seitenzahl steht im Registerreiter
\bdata-slot\b => Platzhalter der Profilvorlage stehen in assets/mappe/master.json (slots)
\bdata-src\b => das Attribut heißt data-origin

# Pins: ein Editor, eine Warteschlange (references/tencil.md, Regel pins.one-writer)
\bandere Pin-Threads berücksichtigen\b => Pin-Threads reihen ein, es schreibt nur der Editor
\bParallele Pin-Threads\b => Pin-Threads reihen ein, es schreibt nur der Editor

# Schemaprüfung braucht keine Installation
\bpip install jsonschema\b => validate nutzt tools/schema_lite.py

# Lebenslauf: Schulbildung vor Erfahrung (references/template.md, Regel cv.block-order)
\bPraktische Erfahrung, Schulbildung, Fähigkeiten\b => Schulbildung steht vor der Praktischen Erfahrung
\bLesereihenfolge `?experience`?, `?education\b => Lesereihenfolge education, experience, skills, languages

# Unterschrift: Die Einwilligung gilt für Anschreiben und Lebenslauf (references/profile-schema.md, Regel person.signature)
\bNur dann im Anschreiben\b => die Unterschrift steht unter dem Anschreiben und am Ende des Lebenslaufs
\bNur mit valid und consent im Anschreiben\b => die Unterschrift steht unter dem Anschreiben und am Ende des Lebenslaufs

# Logos stehen in Markenfarbe (assets/icons/README.md, Regel icons.sources)
\beinfarbige[sn]? Logo\b => Logos stehen in Markenfarbe; einfarbig sind nur die Linien-Icons
\bals einfarbige `?<symbol> => Logos stehen in Markenfarbe; einfarbig sind nur die Linien-Icons

# Anschreiben: fünf feste Absätze, kein Wortziel (references/writing.md, Regeln letter.structure und letter.length)
\bErst kürzen, dann verdichten\b => Anschreiben: erst normal bauen, bei Überlauf dicht, dann kürzen
\bFähigkeiten, nicht Leidenschaft\b => der Aufbau des Anschreibens steht in Regel letter.structure
\blimits:letter\.words\b => das Anschreiben hat kein Wortziel

# Firmenfakten für die Briefe stehen in firma.md (references/job-search.md, Regel company.research)
\bkommt nach `company_facts\[\]` => Aussagen über die Firma für die Briefe stehen in job_information/firma.md
\bFirma \(?aus `?company_facts\b => Aussagen über die Firma für die Briefe stehen in job_information/firma.md

# E-Mail: fester Wortlaut (references/writing.md, Regeln email.text und email.relocation)
\banbei sende ich Ihnen\b => die E-Mail hat einen festen Wortlaut
\bEin Umzug nach [^\n]{0,40} ist für\b => Umzugssatz: „Derzeit wohne ich in …, plane aber, … umzuziehen.“

# Motivationsschreiben: ein Mastertext pro Profil (references/writing.md, Regel motivation.master)
\bMotivationsschreiben und E-Mail werden pro Stelle neu geschrieben\b => das Motivationsschreiben ist ein Mastertext, die E-Mail hat einen festen Wortlaut
